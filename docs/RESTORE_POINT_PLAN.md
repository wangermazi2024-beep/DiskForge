# DiskForge 未来设想：磁盘 / 目录状态还原点（Restore Point）

> 状态：**规划中（未实现）**——本文档是功能设想与实现路线的设计底稿，
> 描述"我们想把它做成什么样、分几步做、每一步的边界在哪"。
> 文中标注 P0~P3 的条目均为未来版本计划，不代表当前版本已具备该能力。

---

## 1. 一句话愿景

让用户可以给**任意一块磁盘或任意一个路径**拍一张"文件目录结构快照"（状态还原点），
之后任何时刻都能**对比出自快照以来的全部增删改**，并把目录结构**还原回快照时刻的样子**——
就像系统还原点，但粒度是文件和文件夹，且由用户自己随时创建。

## 2. 背景与动机

### 2.1 用户痛点

日常使用中存在大量"希望能回到之前状态"的场景，而现有工具都有明显的覆盖空白：

| 场景 | 现有手段 | 缺口 |
|------|----------|------|
| 整理文件夹后后悔，想恢复原目录结构 | 手工重建 / 系统还原点 | 手工重建费时费力；系统还原点不跟踪用户文件变动 |
| 批量删除后想找回被删的文件 | 回收站 | 清空回收站、被脚本/命令行删除、删除发生在很久以前，都无从找回 |
| 想知道"这几天 D 盘到底被删了什么、动了什么" | 无 | 缺少"两个时点之间目录状态差异"的对比能力 |
| 交接/重装前想给某个目录留一份"结构存档" | 截图 / 手写清单 | 无法机读、无法对比、无法还原 |

系统还原点保护的是系统与注册表状态，回收站只保留"最近一次删除"，两者都不能回答
**"这个目录上周是什么样的"** 这个问题。DiskForge 想补的正是这个空白。

### 2.2 DiskForge 的先天优势

DiskForge 的核心能力是 **NTFS MFT 直读**：绕过逐层遍历目录的常规枚举方式，
直接解析 $MFT 记录，几秒钟即可完成对百万级文件全卷的枚举（实测 C: 盘 93 万文件约 10 秒）。
这给"状态还原点"带来了两个天然优势：

- **快照足够快**：常规遍历工具给整盘做快照要跑几分钟甚至更久，用户不愿意等；
  MFT 直读让"给 C 盘拍个快照"变成几秒钟的事，功能才具备日常可用的前提。
- **单文件绿色版即可承载**：快照生成是纯只读操作，不需要驱动、不需要服务，
  与 DiskForge 现有的"单文件、免安装、管理员直读"产品形态完全一致。

## 3. 功能设想（用户视角）

### 3.1 创建还原点

1. 用户在 DiskForge 中选择范围：**整块磁盘**（如 `C:\`）或**某个路径**（如 `D:\项目资料`）；
2. 点击"生成状态还原点"，软件以只读方式扫描该范围内的全部文件与目录；
3. 生成一份**还原点存档文件**（manifest），记录当时每个条目的：
   完整路径、类型（文件/目录）、大小、创建/修改/访问时间、属性、MFT 记录号等元数据；
4. 存档命名形如 `C盘-20260907-1632.restorepoint`，保存位置由用户指定（默认建议独立目录），
   可随意复制、移动、备份——存档本身就是一个自包含文件。

### 3.2 对比差异

打开任一还原点，软件将其与当前磁盘状态对比，输出三类差异清单：

- **已删除**：快照里有、现在没有的文件/目录；
- **新增**：快照里没有、现在多出来的文件/目录；
- **已变化**：路径相同但大小/时间戳/属性发生了变化的条目。

差异清单支持按类型、路径、时间筛选与排序，可导出为 CSV 报告，
让"这段时间这个目录里发生了什么"变得一目了然。

### 3.3 还原

用户选择某个还原点执行还原，可选两种深度：

- **结构还原（P1，承诺可达）**：把目录结构恢复成快照时刻的层级——
  被删掉的**空目录/目录树**按原路径原层级重建，使"骨架"回到从前；
  对"多出来的"文件提供清单与人工处置建议，绝不未经确认就删除现有文件。
- **内容找回（P2，尽力而为）**：对快照中记录、后来被删除的**文件内容**，按以下优先级尝试找回：
  1. **回收站联动**：文件仍在回收站中 → 原路放回原位置（成功率最高，零风险）；
  2. **MFT 残留扫描**：文件的 MFT 记录尚未被新文件覆盖、数据 run 所在簇未被重写 → 直接按记录恢复；
  3. 均不可行 → 在报告中明确标注"内容已无法找回"，只恢复目录骨架。

任何还原动作执行前必须经过**预演（dry-run）**：软件先展示"将会重建哪些目录、
将尝试找回哪些文件、预计结果如何"，用户确认后才真正执行；
还原过程本身只做"重建目录 + 找回文件"，**永不删除现有数据**。

## 4. 分期路线图

| 阶段 | 内容 | 交付判据 |
|------|------|----------|
| **P0 快照与对比（MVP）** | 还原点生成（双枚举通道）、manifest 存储格式、差异对比引擎、差异报告导出 | 给 C 盘做快照 ≤ 15 秒；百万级条目对比 ≤ 5 秒；差异清单与人工核对一致 |
| **P1 结构还原** | 预演报告、目录树重建引擎、操作日志与中断续跑 | 被删目录树按原层级完整重建；预演结果与实际执行结果一致 |
| **P2 内容找回** | 回收站联动放回、MFT 残留记录扫描恢复、恢复成功率报告 | 回收站文件 100% 原路放回；未覆盖 MFT 记录的文件内容可找回 |
| **P3 增量与守护（远期）** | 定时自动快照、多还原点时间轴管理、基于 USN 日志的变动实时监控 | 后台静默快照不干扰前台使用；可在时间轴上任意两点间对比 |

## 5. 技术设计草案

### 5.1 快照生成：双枚举通道

- **MFT 直读通道**（整盘快照首选）：复用现有 `mft_scan` 的 $MFT 解析链路
  （打开卷 → 解析 run 列表 → 逐记录提取路径/大小/时间戳/记录号），只读、秒级；
- **常规枚举通道**（指定路径 / 非 NTFS 卷）：复用现有目录遍历逻辑，虽慢但普适；
- 两通道产出统一的"条目清单"中间结构，后续流程完全一致，上层无需关心来源。

### 5.2 manifest 存储格式

- 采用**带版本号的自定义二进制格式 + 可选压缩**，而不是直接用 JSON：
  百万级条目若存 JSON 约数百 MB，二进制化并按记录紧凑排布后可缩减一个数量级，
  读写也远快于解析大 JSON；
- 文件头包含：格式版本、DiskForge 版本、快照范围、创建时间、卷序列号、条目总数；
- 卷序列号用于把还原点和它所属的卷绑定，防止把 C 盘的还原点错用到 D 盘上；
- 格式版本号从第一天就写入，为未来字段扩展留出向前兼容空间。

### 5.3 对比引擎

- **双键匹配**：主键为"完整路径"，辅键为"MFT 记录号"。路径相同即视为同一条目；
  记录号用于辅助识别"同名但被删除后重建"的情况（记录号变了 = 内容大概率整体换代）；
- 双侧清单均先按路径排序再做归并对比，百万级条目在内存中一次归并完成，避免 O(n²) 哈希开销；
- 大小、时间戳的"变化阈值"可配置（例如忽略 2 秒内的时间戳抖动），减少无意义噪音。

### 5.4 还原引擎

- 严格区分**结构层**（目录树重建：`create_dir_all` 按快照层级补齐）与
  **内容层**（文件数据找回：回收站放回 / MFT 记录恢复），两层独立开关、独立报告；
- 全程写**操作日志**（每一项动作、结果、跳过原因），中断后可凭日志续跑；
- 铁律：还原引擎只"加"不"删"——现有文件与目录永远只出现在报告里，由用户自行处置。

### 5.5 与现有架构的衔接

| 现有模块 | 可复用点 |
|----------|----------|
| `mft_scan.rs` | MFT 直读枚举、run 列表解析、错误回退策略 |
| 现有列表/树视图 | 差异清单展示、按类型筛选着色 |
| 导出模块 | 差异报告导出 CSV |
| 后台任务框架 | 快照/对比/还原全部放入后台线程，进度实时上报主界面（沿用"已发现 X 项"的实时计数方案） |

## 6. 风险与边界（诚实声明）

- **内容找回不承诺 100%**：被删除文件的簇一旦被新数据覆盖，任何软件都无法凭空恢复；
  越早生成还原点、越早执行找回，成功率越高。P1 的"结构还原"是确定性能力，
  P2 的"内容找回"是概率性能力，产品文案与界面必须始终如实区分；
- **快照只含元数据**：还原点不复制文件内容本身（除非未来明确引入"完整备份"模式，
  那是另一个量级的存储与时间成本，不在本设想范围内）；
- **权限与系统目录**：对无权限访问的条目如实记录"跳过"，还原时不越权操作；
- **还原点自身的健壮性**：存档文件损坏时必须能被检测出来（写入校验和），
  绝不能拿一份半损坏的清单去做还原决策。

## 7. 界面设想

- 顶栏新增"还原点"入口，打开独立的还原点面板；
- 创建向导三步走：选范围 → 确认生成 → 完成展示（条目数/耗时/存档路径）；
- 对比视图复用现有列表交互：删除/新增/变化三色标识，支持勾选放大查看单项详情；
- 还原确认弹窗强制走预演结果，风险项（如"此操作将重建 128 个目录"）显著高亮。

## 8. 里程碑建议

1. **M1（P0）**：快照 + 对比 + 报告导出——先用最低成本把"看得见的差异"做出来，
   让功能可用、可验证；
2. **M2（P1）**：预演 + 结构还原——把"可回退"从报告变成动作；
3. **M3（P2）**：内容找回——在 M1/M2 稳定的基础上攻坚概率性恢复；
4. **M4（P3）**：自动快照与时间轴——从"用户主动拍快照"进化为"软件帮用户记住每个时点"。
